## 看点

- **钉住的舞台**：场景用 `position: sticky` 钉在左边，右边每一步是一张卡片，每张至少 62vh 高；手机上舞台钉在顶部，卡片从下面滚过去。
- **当前步 = 越过阅读线的最后一张卡**：宽屏的阅读线在视口 55% 处，窄屏在舞台下方一点；滚动事件合并到 `requestAnimationFrame` 里，每帧最多算一次。
- **镜头只改两个数**：镜头始终从同一个方向看，每一步只改「看哪里」和「离多远」，用指数插值追过去，切步不晕。第 0 步是全景，场景先「收起来」再一站站搭出来。
- **零件弹簧出场**：每一站是一组零件，到了这一步才从地面弹出来（带一点过冲的弹簧），往回滚就收回去；一下跳过几步也会按顺序搭。路上的点按离上一站的远近依次出现，那封小信沿路飞到当前这一站。
- **HTML 标签挂在 3D 点上**：每帧把锚点投影到画布坐标，挂上普通的 HTML 标签；点出了画面就藏起来，上方放不下就挂到下面，左右贴边会往里滑。文字可选、可读屏，也不用在 3D 里排字。
- **代码建模**：桌子、信封、邮筒、邮车、房子都是圆角盒子、圆柱、三角棱柱拼的，没有模型文件要下载；`MeshStandardMaterial` 粗糙度 0.72 + 柔和阴影，就是黏土感。
- **省电**：只有东西在动时才渲染，停下就停掉循环；离开视口也停。偏好减少动效时镜头和零件直接到位。

## 怎么用

1. 拷 `.story-body` 这段结构和样式：左边 `.story-stage > .story-fig`（放画布和 `.pins` 标签层），右边 `<ol class="story-steps">`，每步一个 `data-step`。
2. 在 `build()` 里换成你自己的场景：每一步做一个 `Group` 放进 `pieces`（写上它属于第几步），再给每一站一个锚点 `Object3D` 挂标签。
3. 改 `FOCUS` / `DIST` 两个数组：每一步镜头看哪里、离多远。第 0 步拉远看全景。
4. 标签写在 HTML 里：`<span class="label" data-pin="锚点名" data-step="步号">`，脚本会负责定位和显隐。
5. 首屏要快的话，可以先放一张同机位的静态图，等用户第一次滚动或点击再加载 three.js，加载完淡入画布（画面不会跳）。

## 坑

- 读布局（`getBoundingClientRect`）只在滚动后的那一帧里做，别在加载时、也别和写样式交错着读，否则会强制重排、滚动发卡。
- 画布要设 `touch-action: pan-y`，不然手机上在场景上竖着滑会被拖动吃掉，页面滚不动；拖动只用来左右转一点，松手转回正面。
- 弹簧积分用小的固定步长（这里 1/120 秒），掉帧的时候才不会弹飞。
- 不同宽高比下全景会被裁掉：按「参考宽高比 ÷ 实际宽高比」把镜头拉远一些。
- 没有 WebGL 时舞台显示一句提示，文字步骤照样讲完整个过程；正式用的话最好有一张静态图兜底。
